## Pipeline

GitHub Actions запускает установку, затем последовательно typecheck, lint,
format:check, test:run и build. Триггеры: push в main, pull_request в main,
ручной workflow_dispatch. ОС ubuntu-latest; Node.js 24.x.
Все run-команды выполняются с working-directory homework_6_ci_fix;
cache-dependency-path homework_6_ci_fix/package-lock.json. Разрешение токена
ограничено contents:read; предыдущий запуск той же ветки можно отменить
через concurrency. Модульные тесты подменяют API и не обращаются к реальной БД.

## Локальная проверка Windows

В обычном терминале PowerShell из папки проекта:

```powershell
$env:ComSpec = "$env:SystemRoot\System32\cmd.exe"
npm.cmd ci
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run format:check
npm.cmd run test:run
npm.cmd run build
```

Для применения только форматирования: `npm.cmd run format:write`.
После установки и обновления scripts не нужно повторять npm ci перед
каждой командой. Команды запускаются по очереди, ошибка требует разбора.

## Работа с AI и исправления

Я использовала GigaCode в GigaIDE для первоначального workflow,
скриптов проверок и настройки Prettier. Запуск установки через инструмент
агента не удался, поэтому установку Prettier выполнила в обычном терминале.
Установка завершилась; npm сообщил о 36 уязвимостях (2 low, 7 moderate,
25 high, 2 critical). Подробный аудит цепочек пока не выполнен.

Первый lint выявил неиспользуемые импорты, параметр mock-функции и any,
а также предупреждения React. После нескольких правок GigaCode lint
всё ещё показывал 2 ошибки и 2 предупреждения. Передала текущие исходники
ChatGPT для проверки. Причина: добавленные _event/_session тоже не
использовались, а перенос AuthProvider и useAuth вместе в другой файл
с последующим реэкспортом не устранял смешанные экспорты.

В исправленной версии:

- authContext.tsx содержит контекст и его типы;
- useAuth.tsx содержит только хук;
- AuthProvider.tsx содержит компонент провайдера;
- импорты приложения и теста обновлены;
- ненужные аргументы тестовой mock-функции удалены;
- правила ESLint не отключены;
- файлы проекта отформатированы Prettier;
- реальные .env, node_modules, dist и каталоги IDE исключены.

ESLint и TypeScript проверены в контрольной Linux-среде ChatGPT успешно.
Результаты контрольных проверок записаны отдельно в ci_verification.md.
Итоговый Windows-прогон подтверждён: 31/31 тест, 4.67s; сборка 3.84s.
Первый запуск GitHub Actions потребовал исправления форматирования.

## Безопасность и следующие этапы

.env.local, пароли БД, OAuth Client Secret и токены хостинга не публикуются.
.env.example содержит только имена переменных и безопасные примеры.
VITE-переменные доступны браузеру, поэтому туда нельзя помещать серверные секреты.

На шаге 2 нужно получить npm audit, проанализировать цепочки, обновить
уязвимые зависимости и повторить проверки. Есть предупреждение
typescript-eslint о TypeScript 5.6.3 в текущем Windows-окружении;
совместимость версий тоже проверяется при обновлении зависимостей.
Автоматическое npm audit fix --force не применялось.

Далее подключаются хостинг и deploy после успешных проверок, OAuth2,
аналитика, мониторинг с алертами и Health Check, структурированные логи.
Фактические настройки и результаты будут дописаны после выполнения.
