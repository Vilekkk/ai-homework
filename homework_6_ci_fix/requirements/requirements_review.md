# Проверка полноты и структуры ТЗ с помощью AI

Инструмент проверки: ChatGPT. Проверены документы ДЗ 3 и раздел
«Генерация UI-концепций и технического задания» в файле преподавателя.
Проверка относится к документации, без запуска приложения.

## Задача проверки

Сопоставить документы с требованиями задания: идея и аудитория, минимум три
функции MVP, три разные UI-концепции, обоснование выбора, персоны и пути,
минимум пять приоритезированных историй, критерии Given–When–Then,
негативные сценарии, функциональные и нефункциональные требования.
Найти неоднозначности и согласовать документы между собой.

## Результаты и уточнения

| Проверяемый пункт    | Результат                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Идея и аудитория     | Описаны проблема, ценность, две персоны и функции MVP                                                                  |
| Визуальные варианты  | Три изображения Bolt: светлый список, яркая доска и корпоративная таблица                                              |
| Выбор интерфейса     | Для ТЗ используется концепция 3; приведены преимущества, ограничения и обоснование                                     |
| Истории и приоритеты | Девять историй в формате «Как…, я хочу…, чтобы…», карта Must/Should/Nice                                               |
| Критерии             | У каждой истории не менее трёх критериев Given–When–Then; есть позитивные и негативные сценарии                        |
| Ошибки               | Описаны валидация, пустые состояния, ошибки хранения и реакции по ключевым функциям; сеть и 401/403 — для будущего API |
| Структура ТЗ         | Есть описание проекта, аудитория, функциональные и нефункциональные требования, обработка ошибок                       |
| Границы MVP          | Локальный браузерный интерфейс; API, аккаунты и синхронизация не заявлены реализованными                               |
| Проверки прототипа   | Реально наблюдавшиеся действия отделены от проектных требований                                                        |

## Устранённые неоднозначности

- Общие счётчики рассчитываются по всему списку, независимо от фильтров.
- Пустой список и отсутствие совпадений имеют разные сообщения и действия.
- Фильтры применяются одновременно по AND.
- Приоритет хранится как low/medium/high, отображается русской подписью.
- Сохранение в localStorage — Should have; удаление — Nice to have.
- Мобильность, доступность и ограничения длины включены в критерии будущей
  приёмки; их выполнение не приписано скриншотам настольного прототипа.
- Обработка сетевых ошибок и доступа описана для серверного расширения;
  текущий локальный прототип не выполняет такие запросы.

## Итог

Комплект содержит все артефакты шести шагов инструкции ДЗ 3.
В критериях преподавателя упомянуты семь шагов, но в инструкции перечислены
шесть; дополнительный обязательный шаг из этого не выводится.
Проверка полноты с AI выполнена в рамках шага 6.
