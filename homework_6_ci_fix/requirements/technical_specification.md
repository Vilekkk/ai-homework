# Техническое задание: «Мои задачи»

Версия 1.0 от 15.10.2026. Основа UI: концепция 3, корпоративная таблица.
Документ задаёт требования к реализации; подтверждения текущего прототипа
отдельно перечислены в evidence/verification.md. Будущие требования не
выдаются за уже разработанные возможности.

## 1. Описание проекта и аудитория

Личный веб-менеджер задач для студентов и специалистов. Цель — создавать,
находить и завершать дела на одном экране. Права доступа у персон одинаковы.
Подробная идея: [описание проекта](project_description.md). Истории и полные
критерии: [User Stories](user_stories.md). UI: [сравнение концепций](ui_concepts/ui_description.md).

## 2. Объём и архитектура

MVP работает локально в браузере, без аккаунтов и сервера. Это самостоятельный
прототип интерфейса для идеи task_api, а не интеграция с API предыдущего ДЗ.
Рекомендуемая реализация: React + TypeScript, отдельные представления списка,
формы, фильтров и счётчиков; логика фильтрации и изменения состояния отделена
от UI. Это проектное решение; исходники Bolt не экспортировались и состав
его зависимостей по снимкам не проверялся. Не устанавливать новые библиотеки
лишь ради простых операций фильтрации.

Состояние: tasks, statusFilter, priorityFilter, modalState, formErrors.
Для MVP источник данных — состояние приложения. Should have: адаптер
localStorage с явной обработкой ошибок. Никаких API-ключей на клиенте.

## 3. Модель и инварианты

| Поле        | Тип / правило                                                            |
| ----------- | ------------------------------------------------------------------------ |
| id          | Уникальная строка, генерируется при создании; совпадения не допускаются  |
| title       | Строка после trim, от 1 до 200 символов                                  |
| description | Необязательная строка, до 2000 символов; отсутствующая становится пустой |
| completed   | boolean, по умолчанию false                                              |
| priority    | low / medium / high, по умолчанию medium                                 |
| created_at  | ISO 8601 UTC, устанавливается при создании                               |

UI показывает низкий/средний/высокий; значение «Все» относится только к фильтру.
Порядок списка: активные перед выполненными, внутри группы новые прежде старых;
при равном времени id используется как стабильный дополнительный ключ.
Пагинация и поиск по тексту не входят в MVP.

Общие счётчики вычисляются из tasks: всего = active + completed, фильтры на
счётчики не влияют. Фильтры объединяются по AND. Отсутствие ограничения
не равнозначно false: «Активные» означает completed=false, «Все» — любой статус.
Демонстрационные данные содержат 6 задач при первом запуске; последующая
загрузка не должна дублировать их. Это правило потребуется адаптеру Should have.

## 4. Функциональные требования и качество по функциям

| ID / истории  | Функциональное требование                                                          | Нефункциональное условие и проверка                                                             |
| ------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| FR-01 / US-01 | Список со статусом, названием, описанием, приоритетом и действиями; общие счётчики | Подписи на русском, корректные суммы; пустой список отличается от пустого фильтра               |
| FR-02 / US-02 | Модальная форма создания; trim и границы полей; ошибки у полей; отмена без записи  | Ошибка не закрывает форму и не теряет ввод; кнопка не создаёт дубль при повторной отправке      |
| FR-03 / US-03 | Три допустимых приоритета, средний по умолчанию                                    | Важность передаётся текстом и цветом; неизвестное значение отклоняется                          |
| FR-04 / US-04 | Завершить или вернуть задачу, пересчитать список и счётчики                        | Сохраняются id, название, описание, приоритет и created_at; без перезагрузки                    |
| FR-05 / US-05 | Две группы фильтров, AND, независимое изменение выбранной группы                   | Выбор видим; исходные tasks не изменяются; пустая выдача не считается ошибкой сервера           |
| FR-06 / US-06 | Кнопка сброса на панели и в пустой выдаче                                          | Один клик восстанавливает оба значения «Все» без изменения задач                                |
| FR-07 / US-07 | Should: сериализация списка и загрузка из localStorage                             | Ошибка чтения/записи объясняется; данные не уничтожаются молча; схема имеет версию              |
| FR-08 / US-08 | При ширине менее 768 px карточки, иначе таблица; доступные форма и действия        | Нет горизонтального скролла документа при 360/768/1280 px; Tab, Escape, фокус и доступные имена |
| FR-09 / US-09 | Nice: удаление только после подтверждения                                          | Отмена не меняет данные; удаляется одна запись; счётчики пересчитаны                            |

## 5. Требования к экрану и взаимодействию

Верхняя тёмно-синяя шапка: название и «Добавить задачу». Ниже три счётчика,
панель статуса/приоритета и список. В таблице колонки «Статус», «Название и
описание», «Приоритет», «Действия». Для действий нужны tooltip и aria-label
с назначением и названием задачи. Длинные строки переносятся; содержимое
показывается как текст, не HTML.

Модальное окно: заголовок, обязательное название, необязательное описание,
приоритет, отмена и добавление. При открытии фокус на названии; Tab удерживается
в диалоге; Escape и отмена закрывают его без записи; после закрытия фокус
возвращается к кнопке. Ошибка связана с полем и объявляется доступным сообщением.
Новая корректная отправка очищает ошибки. Если новая задача не подходит под
выбранный фильтр, показать сообщение об успехе и действие «Сбросить фильтры»,
не менять фильтры молча.

## 6. Ошибки, крайние случаи и UX

| Ситуация                                   | Реакция и восстановление                                                                                              | Область                                              |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Пустое/пробельное название                 | Красная рамка и «Введите название задачи — это поле обязательно»; фокус на поле, запись не создана                    | MVP; пустое значение проверено                       |
| Превышены 200/2000 символов                | Ошибка у поля с допустимой длиной, форма и ввод остаются                                                              | Требование MVP; не проверено                         |
| Неизвестный priority                       | Отклонить значение, попросить выбрать из трёх                                                                         | Требование MVP; не проверено                         |
| Нет задач вообще                           | «Пока нет задач» и кнопка добавления, нулевые счётчики                                                                | Требование MVP; не проверено                         |
| Фильтры ничего не дали                     | «Ничего не найдено», пояснение и «Сбросить фильтры»                                                                   | MVP; проверено                                       |
| Завершение при фильтре «Активные»          | Строка исчезает из выборки, понятное уведомление; список не удаляется                                                 | Требование MVP; частично проверена смена без фильтра |
| Хранилище недоступно                       | Предупредить о временном сеансе, сохранить данные в памяти                                                            | Should have; не проверено                            |
| Повреждено сохранение                      | Предложить сброс с подтверждением, не перезаписывать автоматически                                                    | Should have; не проверено                            |
| Нет сети в загруженном локальном прототипе | Сетевые операции отсутствуют, не показывать выдуманную ошибку сохранения на сервере                                   | Текущая архитектура; отдельно не проверено           |
| Сетевая ошибка/таймаут будущего API        | Оставить список и черновик, снять индикатор загрузки, «Не удалось сохранить. Повторить»; повтор не дублирует создание | Только будущая серверная версия                      |
| 401 будущего API                           | Объяснить необходимость входа, предложить вход, не показывать закрытые данные; защиту реализует сервер                | Только будущая авторизация                           |
| 403 будущего API                           | «Недостаточно прав», не повторять запрос автоматически и не менять данные                                             | Только будущие роли                                  |

Сетевые ошибки и неавторизованный доступ спроектированы для возможного
серверного расширения по требованию задания. В текущем локальном MVP нет
закрытых ресурсов, входа или запросов к серверу; их тестирование не заявляется.

### Обработка ошибок по ключевым функциям

| Функция                 | Проверки и негативные сценарии                                                          | UX-решение                                                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Просмотр списка         | Нет задач; повреждённое сохранение при наличии адаптера хранения                        | Различать первый пустой список и ошибку чтения; показать добавление либо предупреждение и подтверждаемый сброс                |
| Создание и приоритет    | Пустое/пробельное название, превышение длины, неизвестный приоритет, повторная отправка | Показать ошибку у поля, сохранить введённое, не создавать запись; блокировать повторную отправку на время операции            |
| Смена статуса           | Задача уже отсутствует либо состояние изменилось до действия                            | Свериться с актуальным списком, не создавать новую задачу; сообщить, что список обновился, пересчитать счётчики               |
| Фильтрация              | Нет совпадений; неизвестное сохранённое значение фильтра                                | Для пустой выборки предложить сброс; некорректное значение заменить на «Все», не изменяя сами задачи                          |
| Сброс фильтров          | Повторный сброс при значениях «Все»                                                     | Оставить список и данные без изменений; ошибка не показывается                                                                |
| Сохранение, Should have | Хранилище недоступно, переполнено либо данные повреждены                                | Предупредить о временном хранении; сохранить текущий список в памяти, не перезаписывать повреждённые данные без подтверждения |
| Удаление, Nice to have  | Отмена, запись уже отсутствует                                                          | При отмене ничего не менять; при отсутствии записи обновить список и пояснить результат                                       |

Если появится серверная версия, для чтения, создания, смены статуса и удаления
действуют общие правила: при сетевой ошибке сохранить доступные данные и
черновик, показать «Повторить»; при 401 предложить вход; при 403 объяснить
отсутствие прав. Не показывать успешное изменение до подтверждения сервера.
Фильтрация и сброс в текущем MVP выполняются локально и не требуют сети.

## 7. Общие нефункциональные требования

- Реакция локального фильтра/смены статуса: до 200 мс для 1000 задач после
  загрузки, измерение 20 действий в браузере на устройстве с 8 ГБ RAM;
  критерий относится к будущей приёмке и сейчас не измерялся.
- Контраст основного текста не ниже 4.5:1, интерактивные элементы доступны
  клавиатурой, зона нажатия на телефоне не менее 44×44 CSS px.
- Не вставлять пользовательские строки как HTML; не писать персональные
  сведения и содержимое задач в технические логи.
- Совместимость: текущие на момент приёмки стабильные Chrome и Firefox,
  проверка ширин 360, 768 и 1280 px; версии браузеров записать в протоколе.
- Ошибка состояния не должна молча уничтожать список; перезапуск сеанса
  с потерей несохранённых данных должен быть явно объяснён пользователю.

## 8. План разработки и приёмки

1. Данные и чистые операции: создание, фильтрация, смена статуса, счётчики.
2. Экран концепции 3, форма и ошибки; адаптация и доступность.
3. Unit-тесты инвариантов, UI-проверки Given–When–Then из user_stories.md.
4. После MVP — отдельное решение о Should/Nice и будущем API.

Definition of Done MVP: US-01—US-06 и US-08 реализованы и их критерии пройдены;
скриншоты desktop/mobile, результаты функциональных проверок и ограничения
зафиксированы. Для сдачи текущего ДЗ требуется пакет проектирования;
описанные критерии не означают, что все возможности уже реализованы.
