# ДЗ 2. Проект, стек и стандарты разработки

## Проект и задача

Я выбрала учебный проект управления задачами task_api. Для него подготовила
правила работы с AI-агентом и библиотеку запросов. Практическую часть выполнила
в GigaIDE с GigaCode / CodeAgent, режим «Агент», 14 октября 2026 года.

В ДЗ 2 я работала с отдельной функцией над списком словарей:
`id`, `title`, `completed`, `priority`. Сначала сравнила фильтрацию без правил
и с правилами. Затем через три последовательных запроса получила план,
реализацию фильтрации с пагинацией и тесты.
Рабочие файлы цепочки: `hw2_examples/task_filter.py` и
`hw2_examples/test_task_filter.py`.

## Стек

Контекст проекта для правил: Python, FastAPI, SQLAlchemy, SQLite, Pydantic,
Uvicorn; тестирование — pytest. В практической задаче нужны Python и pytest:
функция обрабатывает данные в памяти и не обращается к базе.
В выводе реального запуска указаны Python 3.15.0 и pytest 9.1.1, Windows.
Версии остальных библиотек в этой работе отдельно не проверялись.

## Архитектура и стандарты

Для API я задала разделение ответственности: HTTP-маршруты — `routers`,
запросы к базе — `crud`, модели — `models`, схемы валидации — `schemas`.
Выполненная в ДЗ 2 функция и её тесты находятся отдельно в `hw2_examples`.

Основные требования:

- аннотации типов параметров и результата;
- `snake_case` для функций и переменных, `PascalCase` для классов;
- краткие русские пояснения и английские идентификаторы;
- именованные необязательные параметры;
- проверка отсутствия фильтра через `None`, сохранение значений `False` и `0`;
- сохранность исходных данных;
- проверки корректных, ошибочных и граничных случаев;
- отсутствие паролей и ключей в коде и документации;
- сообщение результата тестов только после реального запуска.

## Границы работы

Новые маршруты API и изменения базы в эту практику не входили.
Числовой приоритет в небольшом сравнительном запросе и строковые
`low/medium/high` в последующей цепочке относятся к разным условиям задач.
В исходном сравнительном запросе тип приоритета не уточнялся.
